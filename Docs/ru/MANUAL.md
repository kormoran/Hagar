# HAGAR — Руководство пользователя

Версия: **0.7.0**

Это руководство описывает наблюдаемое поведение Hagar: команды,
параметры, конфигурацию, политики и случаи ошибок. О внутреннем устройстве
см. [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

# 1. Быстрый старт

Требования: Python 3.11 или выше.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

cp hagar.example.yaml hagar.yaml
mkdir -p vault logs

hagar --config hagar.yaml
```

В Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item hagar.example.yaml hagar.yaml
New-Item -ItemType Directory -Force vault, logs
hagar --config hagar.yaml
```

`hagar.yaml`, `testvault/` и `logs/` являются локальными и не подлежат
версионированию.

## 1.1 Порядок запуска

1. Hagar читает конфигурацию.
2. Загружает `policy.yaml`; если он недействителен, применяет `DENY` ко всему.
3. Создаёт клиент LLM.
4. Инициализирует Vault и память, если они настроены.
5. Создаёт файловую песочницу.
6. Регистрирует локальные инструменты.
7. Пытается загрузить серверы MCP; сбой одного сервера не останавливает остальные.
8. Показывает выбор проекта.
9. Входит в цикл чата.

# 2. Команды чата

Команды начинаются с `/`. Неизвестная команда **не отправляется
модели**: Hagar отвечает `Comando sconosciuto` и предлагает `/help`.

## 2.1 Глобальные команды

| Команда | Поведение |
|---|---|
| `/help` или `/?` | перечисляет доступные команды |
| `/tools [категория]` | перечисляет инструменты и возможности; фильтр необязателен |
| `/status` | показывает модель, проект, память, аудит и песочницу |
| `/usage` | показывает токены, израсходованные в сессии |
| `/models ...` | карточки, бенчмарки и оборудование для брокера |
| `/models hardware` | определяет CPU, RAM и GPU машины |
| `/undo` | отменяет изменения последнего хода |
| `/mcp` | перечисляет серверы MCP, endpoint и импортированные инструменты |
| `/audit [n]` | показывает последние `n` событий; по умолчанию 10, максимум 50 |
| `exit` | выход |
| `quit` | выход |
| `Ctrl-D` | выход |
| `Ctrl-C` | прерывает; во время OAuth выходит с кодом 130 |

`/status` и `/audit` — человеческие команды: они не проходят через модель
и не расходуют вызовы инструментов.

## 2.2 Проект

| Команда | Поведение |
|---|---|
| `/project` или `/project list` или `/project ls` | перечисляет активные проекты |
| `/project new <имя>` | создаёт проект и выбирает его |
| `/project select <id>` или `/project use <id>` | выбирает активный проект |
| `/project free` или `/project none` | переходит к свободной деятельности |
| `/project status` или `/project current` | показывает текущий проект |
| `/project archive <id>` | архивирует проект |
| `/project unarchive <id>` | реактивирует архивный проект |
| `/project help` | справка |

`select` и `archive` используют **id** проекта, а не заголовок.

В свободной деятельности память проекта не читается и не записывается; чат,
сводки и навыки остаются доступными.

## 2.3 Память

| Команда | Поведение |
|---|---|
| `/memory` или `/memory help` или `/memory ?` | справка |
| `/memory list [candidate\|confirmed\|archived]` | перечисляет навыки и счётчики |
| `/memory show <slug>` | показывает навык |
| `/memory search <текст>` | ищет в памятях SQLite |
| `/memory sessions` | перечисляет зарегистрированные чаты |
| `/memory chat <session>` | показывает ходы чата |
| `/memory reindex` | оптимизирует/перестраивает индексы SQLite |
| `/memory stats` | состояние и счётчики базы данных |
| `/memory backup <path>` | согласованная копия базы данных |
| `/memory export <path> [--force]` | экспортирует чаты, навыки, сводки и проекты в Markdown |
| `/memory import <path> [--force]` | импортирует структуру Markdown в базу данных |
| `/memory review` | интерактивная проверка кандидатов |
| `/memory confirm <slug>` | подтверждает навык |
| `/memory archive <slug>` | архивирует навык |
| `/memory archive search <текст>` | ищет в архивных транскриптах |
| `/memory archive read <session> [offset] [limit]` | читает архивный транскрипт |

Слова `search` и `read` зарезервированы: slug навыка, называющийся
ровно `search` или `read`, нельзя архивировать этой командой.

Команды удаления не существует: допускается только архивирование.

Бэкенд по умолчанию — SQLite (`memory.backend: sqlite`). База данных
хранится в локальных данных приложения, а не в Vault:

```text
%LOCALAPPDATA%/Hagar/memory.db
```

или `HAGAR_MEMORY_DB`. Бэкенд `markdown` остаётся только для
совместимости. Vault больше не обновляется бэкендом SQLite.

## 2.4 Что не является командой

Инструменты (`filesystem.*`, `memory.*`, `mcp.*`, `clock.now`, ...) вызываются
моделью через registry. Они не вводятся как `/tool`.
Единственное исключение — информационные команды `/tools`, `/status`, `/models`, `/mcp`,
`/audit`, которые являются консольными, а не инструментами.

# 3. Командная строка

```text
hagar [параметры]
hagar web [параметры]
```

| Параметр | Эффект |
|---|---|
| `--config PATH` | использует явный файл конфигурации |
| `--model NAME` | переопределяет `model.name` |
| `--project NAME` | выбирает активный проект при запуске |
| `--free` | запускает в режиме свободной деятельности |
| `--no-memory` | отключает память и проекты для сессии |
| `--no-native-tools` | принудительно включает текстовый JSON-протокол |
| `--hifi` | включает предварительный проход интерпретации и уточнения |
| `--host HOST` | хост веб-GUI (по умолчанию `127.0.0.1`) |
| `--port PORT` | порт веб-GUI (по умолчанию `8765`) |
| `--version` | печатает версию |

`--project` и `--free` взаимоисключающие.

## 3.0 Веб-GUI

```bash
hagar web
hagar --config hagar.yaml web --port 8765
```

Открывает локальный GUI по адресу `http://127.0.0.1:8765/`.

- Сервер рассчитан на одного локального пользователя: по умолчанию `127.0.0.1`.
- Браузер получает случайный токен на странице; API требует его
  в заголовке `X-Hagar-Token`.
- Чат показывает ходы, вызовы инструментов, результаты и подтверждения ASK.
- Вверху расположены вкладки **Chat**, **Chat history**, **Tool output**,
  **Audit** и **Thinking**.
- **Chat history** перечисляет прошлые чаты по одной строке на чат; щелчок
  возобновляет чат: транскрипт перезагружается из базы данных, а новые
  ходы добавляются в ту же сессию.
- Кнопка **+ Новый чат** открывает новую сессию и сбрасывает
  контекст; предыдущий чат остаётся в истории.
- **Memories** — браузер индексированных заметок только для чтения
  (навыки, проекты, решения); позволяет искать и открывать текст.
- **Tool output** показывает вызовы инструментов и результаты сессии.
- **Audit** показывает события журнала; если аудит отключён, вкладка
  отключена и показывает `audit off`.
- **Thinking** показывает рассуждения, предоставленные провайдером, если они есть; в
  противном случае — временную шкалу событий агента.
- **Memories** показывает памяти и навыки базы данных только для чтения, с поиском.
- Кнопка **Stop** кооперативно прерывает ход.
- Кнопка **Immagine** прикрепляет PNG/JPEG/WebP (максимум 4, по 10 MB)
  для моделей vision. WebP конвертируется в PNG в GUI, потому что LM
  Studio не принимает его напрямую. Изображения не сохраняются
  в памяти или аудите: модели передаётся data URL, а не
  путь на хосте.
- Боковая панель внизу показывает суммарные токены сессии: input,
  output и total.
- Модель может загружать изображения из песочницы с помощью `vision.open`;
  изображение прикрепляется к ходу, а не возвращается как base64 в
  контексте.
- Подтверждения ASK модальные: ход остаётся в ожидании, а сервер
  продолжает отвечать. Тайм-аут равносилен отказу. Запросы
  субагентов показывают `agent_id` и `parent_id`; родительская LLM не может
  их одобрить. Тайм-аут субагента — 180 секунд.
- В CLI только один поток владеет вводом. Когда активно подтверждение,
  заголовок терминала привлекает внимание, и принимаются `F5` =
  allow, `F8` = deny, а также `y/N`. Если терминал не поддерживает
  функциональные клавиши, остаются `y/N` и GUI.
- Ctrl-C в CLI восстанавливает нормальный режим терминала перед
  выходом.
- GUI пока не многопользовательский и не предоставляет прямых изменений памяти.
- Ctrl-C закрывает сервер и пытается завершить сессию.

Не используйте `--host 0.0.0.0` в недоверенной сети: GUI открывает
инструменты harness любому, кто может достичь порта.

## 3.1 Поиск конфигурации

Порядок:

1. `--config PATH`
2. переменная `HAGAR_CONFIG`
3. `./hagar.yaml` в текущем каталоге

Относительные пути внутри `hagar.yaml` — аудит, политика, Vault — разрешаются
относительно каталога файла конфигурации, а не каталога, из которого
вы запускаете Hagar.

## 3.2 Коды выхода

| Код | Значение |
|---|---|
| `0` | нормальный выход или `--version` |
| `1` | ошибка конфигурации или недействительный проект |
| `130` | прерывание по Ctrl-C |

Ошибка MCP не меняет код выхода: она регистрируется, и
harness продолжает работу.

# 4. `hagar.yaml`

Минимальный пример:

```yaml
model:
  provider: ollama
  name: llama3.1:latest

vault:
  path: ./vault

filesystem:
  sandbox:
    - alias: workspace
      path: .
      permissions: RX
```

## 4.1 `model`

| Поле | По умолчанию | Примечания |
|---|---|---|
| `provider` | обязательно | `ollama`, `lmstudio`, `deepseek`, `openai` (`chatgpt`), `claude`, `gemini` |
| `name` | обязательно | имя модели у провайдера |
| `host` | по умолчанию провайдера | базовый URL API |
| `native_tools` | `true` | если `false`, использует текстовый JSON-протокол |
| `max_tokens` | `1024` | используется только Claude |
| `timeout` | `120` | тайм-аут HTTP в секундах на каждый вызов |
| `api_key_env` | стандартное имя | переменная окружения ключа |

Провайдеры и ключи:

| Провайдер | Стандартный ключ | По умолчанию |
|---|---|---|
| `ollama` | нет | `http://localhost:11434` |
| `lmstudio` | нет, опционально `LMSTUDIO_API_KEY` | `http://localhost:1234/v1` |
| `deepseek` | `DEEPSEEK_API_KEY` | API DeepSeek |
| `openai` / `chatgpt` | `OPENAI_API_KEY` | `https://api.openai.com/v1` |
| `claude` | `ANTHROPIC_API_KEY` | API Anthropic |
| `gemini` | `GEMINI_API_KEY` | API Gemini |

Ключи никогда не следует писать в YAML. Если ключ отсутствует, клиент
не создаётся и запуск завершается с явной ошибкой. LM Studio
не требует ключа, если только локальный сервер не настроен
требовать его. `chatgpt` — алиас `openai`: подписка ChatGPT не
даёт доступа к API, нужны ключ OpenAI и кредит API.

С LM Studio нативный вызов инструментов зависит от модели и её
шаблона. Если модель принимает запрос, но отвечает текстом вместо
выдачи `tool_calls`, Hagar не может выполнить инструмент: используйте
`model.native_tools: false` или модель с поддержкой инструментов.

При активном нативном вызове Hagar использует структурированные инструменты
провайдера. Если провайдер отклоняет схему (HTTP 400/404/422), на первом
шаге происходит переход на текстовый JSON-протокол для этой сессии. Fallback
покрывает техническую ошибку, но не гарантирует, что модель выберет инструмент правильно.

## 4.2 `audit`

```yaml
audit:
  enabled: true
  path: logs/audit.jsonl
  max_field_chars: 2000
  max_bytes: 5000000
  max_files: 100
  include_outputs: true
```

| Поле | По умолчанию | Эффект |
|---|---|---|
| `enabled` | `true` | включает/отключает журнал |
| `path` | `logs/audit.jsonl` | файл JSON Lines |
| `max_field_chars` | `2000` | усекает поля |
| `max_bytes` | `5000000` | порог ротации |
| `max_files` | `100` | число сохраняемых ротированных файлов |
| `include_outputs` | `true` | если `false`, скрывает вывод инструментов |

Аудит содержит чувствительные данные: вывод файлов, ответы и тексты. Его нужно
защищать так же, как workspace. `/audit` показывает только события текущего
файла, но не ротированные.

Основные события: `harness.start`, `turn.start`, `llm.tool_choice`,
`tool.call`, `tool.result`, `turn.answer`, `permission.decision`,
`permission.confirmation`, `memory.*`, `mcp.loaded`, `mcp.failed`,
`harness.stop`.

## 4.3 `policy`

```yaml
policy:
  path: policy.yaml
  subject: assistant
```

`path` указывается относительно конфигурации. Если файл не читается или
недействителен:

- все политики становятся `DENY`;
- регистрируется `policy.failed`;
- Hagar остаётся запущенным, но ни один инструмент не выполняется;
- консоль показывает `Policy: DENY ALL`.

## 4.4 `vault`

```yaml
vault:
  path: ./vault
```

С бэкендом SQLite он используется только legacy-бэкендом Markdown и
legacy-проектами. При `memory.backend: sqlite` его может даже не существовать.

## 4.5 `memory`

```yaml
memory:
  enabled: true
  backend: sqlite
  database: ./hagar-memory.db
  vault_subdir: Hagar
  context_turns: 10
  context_skills: 3
  context_project_memories: 10
  max_context_chars: 6000
  project_max_active: 200
  summary_max_chars: 4000
  max_skill_chars: 4000
```

| Поле | По умолчанию | Эффект |
|---|---|---|
| `enabled` | `true` | включает память |
| `backend` | `sqlite` | `sqlite` или legacy `markdown` |
| `database` | локальные данные | явный путь к базе данных SQLite |
| `vault_subdir` | `Hagar` | подкаталог legacy Vault |
| `context_turns` | `10` | внедряемые последние ходы; `0` отключает |
| `context_skills` | `3` | внедряемые подтверждённые навыки |
| `context_project_memories` | `10` | заголовки активных решений |
| `max_context_chars` | `6000` | бюджет блока памяти |
| `project_max_active` | `200` | порог обслуживания проектов |
| `summary_max_chars` | `4000` | максимальная длина сводки |
| `max_skill_chars` | `4000` | максимальная длина навыка |

`vault_subdir` должен оставаться внутри Vault: абсолютные пути, `..`,
`I:/...` и другие диски Windows отклоняются даже в Linux.

При `backend: sqlite` база данных по умолчанию:

```text
%LOCALAPPDATA%/Hagar/memory.db
```

или `HAGAR_MEMORY_DB`. SQLite использует WAL, транзакции и `VACUUM INTO` для
резервного копирования; Vault не обновляется.

Бюджет измеряется в **символах**, а не в токенах. Когда блок обрезается,
аудит регистрирует `memory.context_trimmed`.

## 4.6 `filesystem`

```yaml
filesystem:
  sandbox:
    - alias: documenti
      path: C:\Users\pippo\Documenti
      permissions: RWX
  limits:
    max_write_bytes: 0
    min_free_bytes: 0
    session_write_bytes: 0
    ask_over_bytes: 0
```

Каждая запись:

| Поле | Обязательно | Примечания |
|---|---|---|
| `alias` | да | один сегмент, уникальный без учёта регистра |
| `path` | да | существующий каталог хост-системы |
| `permissions` | нет | по умолчанию `R`; буквы `R`, `W`, `X` |

Разрешения:

| Буква | Покрывает |
|---|---|
| `R` | чтение, листинг, поиск, `stat` |
| `W` | запись, создание, переименование, копирование, удаление |
| `X` | `chdir` в каталог |

Агент видит `/home/ai/<alias>/...`. `/home/ai` перечисляет алиасы, но
не является физическим каталогом, и войти в него с помощью `chdir` невозможно.

Ограничения:

- дублирующиеся алиасы и пути останавливают конфигурацию;
- отсутствующий путь останавливает конфигурацию;
- физические пути могут содержать пробелы; алиасы — нет;
- Hagar не создаёт каталоги песочницы и не предполагает отдельный домашний каталог.

Ограничения записи:

| Поле | Эффект |
|---|---|
| `max_write_bytes` | максимум на отдельную операцию |
| `min_free_bytes` | минимальное остаточное свободное место |
| `session_write_bytes` | максимум суммарно за сессию |
| `ask_over_bytes` | сверх этого порога запрашивает подтверждение |

`0` отключает отдельное ограничение. Ограничения являются инвариантами:
их превышение — ошибка инструмента, а не предупреждение.

## 4.7 `permissions`

```yaml
permissions:
  read: true
  write: false
  shell: false
  network: false
  agents: false
```

Это **системный потолок**. По умолчанию: `read=true`, остальные `false`.

| Поле | Предоставляет |
|---|---|
| `read` | filesystem read, memory read |
| `write` | filesystem write/create/delete, memory write |
| `shell` | `FILESYSTEM_EXEC` |
| `network` | `NETWORK` |
| `agents` | `AGENT_SPAWN` и `AGENT_DATA`, для `agent.*`/`artifact.*`/`mailbox.*` |

`COMPUTE` и `MCP_CALL` всегда входят в потолок, но политика может их запретить.
Если потолок не предоставляет возможность, политика не может её предоставить.
`agents: true` само по себе недостаточно: в политике должно быть правило
`AGENT_SPAWN` для `agent.*`.

## 4.8 `rag`

```yaml
rag:
  top_k: 8
```

Ожидаемое значение для поиска по документам. В этой версии оно не изменяет
контекст памяти.

## 4.9 `mcp_servers`

```yaml
mcp_servers:
  - endpoint: https://mcp.example.com/mcp
    namespace: example
    auth:
      type: bearer
      token_env: MCP_EXAMPLE_TOKEN
```

Поля:

| Поле | Примечания |
|---|---|
| `endpoint` | URL HTTP/JSON-RPC сервера MCP |
| `namespace` | префикс импортированных инструментов: `mcp.<namespace>.*` |
| `auth` | опционально: `bearer`, `header` или `oauth` |

Bearer/header:

```yaml
auth:
  type: header
  header: Authorization
  token_env: ATLASSIAN_BASIC
```

Значение, прочитанное из окружения, отправляется **как есть**: для Basic
оно уже должно быть `Basic <base64>`, а не просто токен.

OAuth:

```yaml
auth:
  type: oauth
  oauth:
    authorization_server: https://auth.example.com
    client_id: ...
    client_secret_env: MCP_CLIENT_SECRET
    scopes: [read:me, offline_access]
    audience: api.atlassian.com
    redirect_port: 8765
    token_cache: .hagar/oauth/example.json
    timeout: 300
```

Поток — authorization code + PKCE с локальным callback
`http://localhost:<port>/oauth/callback`. Если `client_id` отсутствует, предпринимается
попытка dynamic registration. При `offline_access` добавляется
`prompt=consent`. Токены находятся в локальном файле с ограниченным доступом и
обновляются автоматически.

Если сервер MCP даёт сбой:

- регистрируется `mcp.failed`;
- сервер пропускается;
- остальные серверы и остальной harness продолжают работу;
- `/mcp` показывает ноль инструментов для этого пространства имён.

## 4.10 `hifi`

```yaml
hifi:
  enabled: true
  margin: 0.20
  interpretations: 3
```

`margin` — минимальное расстояние в процентных пунктах между первой и
второй интерпретацией. Ниже этого порога Hagar запрашивает уточнение.
`interpretations` — число интерпретаций, запрашиваемых у модели.
Режим добавляет один вызов LLM на каждый ход.

## 4.11 `tools`

```yaml
tools:
  timeout: 120
  repeat_limit: 3
```

`timeout` — предел в секундах для отдельного вызова инструмента; `0`
отключает его. `repeat_limit` блокирует третий идентичный вызов в том же
ходе; `0` отключает блокировку. Тайм-аут уже выполняющегося обработчика
Python является best effort: worker может завершиться после предела.

## 4.12 `dev`

```yaml
dev:
  enabled: false
  recipes: recipes.yaml
  copy_workspace: true
  max_output_chars: 100000
```

Включает `dev.list` и `dev.run`, которые выполняют доверенные рецепты для
тестов, отладки и сборки. `recipes.yaml` должен находиться вне песочницы и
читается только при запуске. Также нужна возможность `DEV_EXEC` в политике.
Подробности в `DEV_RUN.md`.

## 4.13 `boxes`

```yaml
boxes:
  enabled: false
  max_input_chars: 200000
  max_output_chars: 20000
  chunk_chars: 8000
  max_calls: 20
```

Включает `box.list` и `box.run` — ограниченные LLM-преобразования файлов
песочницы. У них нет памяти, инструментов или свободного промпта. Нужна
`BOX_EXEC` в политике. Подробности в `BOXES.md`.

## 4.14 `flow`

```yaml
flow:
  enabled: false
  max_source_chars: 20000
  max_steps: 10000
  max_tool_calls: 50
  max_loop_iterations: 1000
  timeout: 120
  max_output_chars: 20000
  repair_attempts: 2
```

Включает `flow.reference`, `flow.validate` и `flow.run` — линейный DSL
`Hagar Flow`. Это не полный Python: без import, class, def, lambda,
try, dict/set comprehension или доступа к объектам Python; разрешены
list comprehension с единственным `for`. Нужна `FLOW_EXEC` в политике;
примитивы `fs.*` используют возможности файловой системы.

`repair_attempts` — максимальное число попыток `flow.repair`;
`0` отключает исправление. `flow.run` никогда не исправляет код сам:
он возвращает ошибку, и вызывающий решает, использовать ли `flow.repair`.
При активной памяти доступны `memory.search`, `memory.context`
и `memory.skill`; при активном проекте — `project.context`.
Подробности в `FLOW.md`.

# 5. `policy.yaml`

Пример:

```yaml
version: 1
subjects:
  assistant:
    default: deny
    rules:
      - capabilities: [FILESYSTEM_READ]
        effect: allow
        tools: ["filesystem.*"]

      - capabilities: [FILESYSTEM_WRITE, FILESYSTEM_CREATE]
        effect: ask
        tools: ["filesystem.*"]

      - capabilities: [COMPUTE]
        effect: allow
        tools: ["calculator.*", "statistics.*", "units.*",
                "clock.*", "calendar.*", "think.*", "text.*", "url.*"]

      - capabilities: [MCP_CALL]
        effect: ask
        tools: ["mcp.*"]

      - capabilities: [MEMORY_READ]
        effect: allow
        tools: ["memory.*"]

      - capabilities: [MEMORY_WRITE]
        effect: ask
        tools: ["memory.*"]
```

## 5.1 Эффекты

| Эффект | Значение |
|---|---|
| `allow` | инструмент может быть выполнен |
| `ask` | требуется человеческое подтверждение |
| `deny` | инструмент не выполняется |

Порядок строгости: `DENY > ASK > ALLOW`. При нескольких требуемых возможностях
действует AND: побеждает наихудший эффект.

`ASK` без канала подтверждения равносилен `DENY`. Подтверждение из консоли
показывает `lo faccio? (y/N)`, по умолчанию — `N`.

## 5.2 Возможности

| Имя | Использование |
|---|---|
| `FILESYSTEM_READ` | чтение, листинг, поиск, stat |
| `FILESYSTEM_WRITE` | изменение |
| `FILESYSTEM_CREATE` | создание, копирование, переименование в назначении |
| `FILESYSTEM_DELETE` | удаление |
| `FILESYSTEM_EXEC` | вход/выполнение в песочнице |
| `MEMORY_READ` | чтение памяти |
| `MEMORY_WRITE` | запись памяти |
| `NETWORK` | сетевой доступ |
| `MCP_CALL` | вызов инструмента MCP |
| `COMPUTE` | локальные вычисления без сети/файловой системы |
| `AISH` | выполнение языка AIsh |
| `DEV_EXEC` | выполнение рецептов dev.run |
| `BOX_EXEC` | выполнение boxed transform |
| `FLOW_EXEC` | выполнение DSL Hagar Flow |

## 5.3 Правила и специфичность

Правило может фильтровать по:

- `tools`: glob по имени (`filesystem.*`, `mcp.atlassian.*`);
- `paths`: префиксы пути, записанного моделью;
- `namespaces`: префиксы пространства имён.

Побеждает наиболее специфичное правило: сначала по числу фильтров, затем по
длине префикса. При равенстве побеждает более строгий эффект.
Без правил действует `default` субъекта; безопасное значение по умолчанию — `deny`.

`AISH` запрещена правилом по умолчанию `aish.*`. Чтобы включить AIsh,
пользователь должен изменить это правило на `allow`; внутренние команды
по-прежнему подчиняются правилам соответствующих инструментов.

Область `paths` сравнивает путь, **записанный моделью**, а не тот, что
получен после `chdir`: абсолютный путь или смена каталога могут не
совпасть и приводят к `DENY` (fail closed).

## 5.4 Ошибки

Если `policy.yaml` недействителен, отсутствует возможность или субъект не
существует:

- Hagar применяет `DENY` ко всем политикам;
- регистрирует `policy.failed`;
- показывает предупреждение;
- не выполняет ни один инструмент.

# 6. Поведение по умолчанию

| Ситуация | Поведение |
|---|---|
| Нет `hagar.yaml` | ошибка конфигурации, выход 1 |
| Недействительный YAML | ошибка конфигурации, выход 1 |
| Недействительная политика | полный DENY, harness запущен |
| Память отключена | проверьте `memory.database` и разрешения каталога |
| `Projects: disabled` | проверьте базу данных SQLite или `vault.path` в legacy-бэкенде |
| Нет активного проекта | свободная деятельность |
| Неинтерактивный запуск | свободная деятельность, если не указаны `--project`/`--free` |
| `--project` не существует | ошибка, выход 1 |
| Сервер MCP недоступен | `mcp.failed`, сервер пропущен |
| Модель/Ollama недоступна | ошибка хода, harness остаётся активным |
| Отсутствует ключ API | клиент не создан, ошибка при запуске |
| Инструмент запрещён | результат-ошибка модели, выполнения нет |
| Инструмент в `ASK` без подтверждения | отказ |
| Превышен лимит записи | ошибка инструмента, записи нет |
| Файл больше 4096 байт с `read_file` | ошибка, используйте `read_chunk` |
| `write_file`/`edit_file`/`delete_file`/`rename` для непрочитанного файла | ошибка: сначала прочитайте файл |
| Файл изменён после чтения | ошибка: перечитайте перед изменением |
| `edit_file` с неоднозначным `old_string` | ошибка: используйте `replace_all` или более конкретную строку |
| `edit_file` с отсутствующим `old_string` | ошибка, изменения нет |
| Страница сверх лимита | `has_more`/`next_offset` |
| Symlink | невидим; операция как с несуществующим путём |
| Hard link/mount/junction | не обнаруживаются; ответственность пользователя |
| Гонка TOCTOU | не контролируется; ответственность пользователя |
| Нет памяти во время хода | `memory.failed`, ход продолжается |
| Конец сессии с ходами | сводка, архив, проверка проекта |
| Проверка отклонена | решения-кандидаты с `auto_saved: true` |
| Проект сверх `project_max_active` | запрос на архивирование |
| Ctrl-C во время OAuth | callback закрыт, выход 130 |
| Неизвестная команда `/` | сообщение, не отправленное модели |

## 6.1 Конец сессии

При выходе, если память активна и есть ходы:

1. транскрипт перемещается в `archive/chat/`;
2. генерируется сводка (LLM, с механическим fallback);
3. сводка сохраняется со ссылкой и хешем;
4. если есть проект, LLM предлагает решения-кандидаты;
5. пользователь может их просмотреть; при отказе они остаются кандидатами.

Если ходов нет, сводка не создаётся.

## 6.2 Что Hagar не делает

- не выполняет команды shell;
- не передаёт модели физические пути;
- не гарантирует изоляцию на уровне ОС: песочница основана на путях;
- не контролирует hard link, mount, junction или TOCTOU;
- не удаляет чаты или навыки по давности;
- не шифрует Vault;
- не превращает автоматически навык или решение в истину.

# 7. Операционная безопасность

- Модель недоверенная: политики и подтверждения — это механизмы контроля.
- База данных SQLite содержит разговоры и решения: её нужно защищать.
- Аудит может содержать вывод файлов: его нужно защищать.
- Ключи API хранятся только в окружении.
- Токены MCP/OAuth хранятся в локальных кэшах с ограниченными правами.
- Не открывайте Ollama или LM Studio в сеть без необходимости.
- Hard link или mount внутри разрешённого каталога может открыть
  внешнее содержимое: Hagar их не обнаруживает.

# 8. Устранение неполадок

| Симптом | Проверка |
|---|---|
| `Policy: DENY ALL` | проверьте `policy.yaml` и `policy.path` |
| `Memory: disabled` | проверьте `memory.database` и разрешения |
| `Projects: disabled` | проверьте базу данных SQLite |
| `Failed to load MCP server` | endpoint, токен, `/mcp` |
| `MCP auth token missing` | переменная, указанная в `token_env` |
| `MCP HTTP 401` | учётные данные/заголовок Basic или OAuth |
| `MCP HTTP 400` | протокол, сессия или параметры сервера |
| `read_file` слишком большой | используйте `read_chunk` |
| `PermissionError` | политика, разрешения `R/W/X`, путь вне песочницы |
| Инструмент не в списке | сервер MCP дал сбой или инструмент не зарегистрирован |
| Команда не распознана | `/help` |

При ошибке конфигурации Hagar завершается с кодом 1 и печатает
подробности в stderr. При ошибке хода модель получает
результат инструмента, а аудит сохраняет событие.
