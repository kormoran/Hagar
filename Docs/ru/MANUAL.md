# HAGAR — Руководство пользователя

Версия: **0.3.0**

Это руководство описывает наблюдаемое поведение Hagar: команды,
параметры, конфигурацию, политики и случаи ошибок. О внутреннем устройстве проекта
см. [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

# 1. Быстрый старт

Требования: Python 3.11 или выше.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"

cp hagar.example.yaml hagar.yaml
mkdir -p vault logs

hagar --config hagar.yaml
```

В Windows:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item hagar.example.yaml hagar.yaml
New-Item -ItemType Directory -Force vault, logs
hagar --config hagar.yaml
```

`hagar.yaml`, `testvault/` и `logs/` являются локальными и не подлежат версионированию.

## 1.1 Порядок запуска

1. Hagar читает конфигурацию.
2. Загружает `policy.yaml`; если он недействителен, применяет `DENY` ко всему.
3. Создаёт клиент LLM.
4. Инициализирует Vault и память, если они настроены.
5. Создаёт файловую sandbox.
6. Регистрирует локальные инструменты.
7. Пытается загрузить серверы MCP; сбой одного сервера не останавливает остальные.
8. Показывает выбор проекта.
9. Входит в цикл чата.

# 2. Команды чата

Команды начинаются с `/`. Неизвестная команда **не отправляется
модели**: Hagar отвечает `Comando sconosciuto` и предлагает `/help`.

## 2.1 Глобальные команды

| Команда | Поведение |
|---|---|
| `/help` или `/?` | перечисляет доступные команды |
| `/tools [категория]` | перечисляет инструменты и capability; фильтр необязателен |
| `/status` | показывает модель, проект, память, аудит и sandbox |
| `/mcp` | перечисляет серверы MCP, endpoint и импортированные инструменты |
| `/audit [n]` | показывает последние `n` событий; по умолчанию 10, максимум 50 |
| `exit` | выход |
| `quit` | выход |
| `Ctrl-D` | выход |
| `Ctrl-C` | прерывание; во время OAuth завершается с кодом 130 |

`/status` и `/audit` — это команды для человека: они не проходят через модель и
не расходуют вызовы инструментов.

## 2.2 Проект

| Команда | Поведение |
|---|---|
| `/project` или `/project list` или `/project ls` | перечисляет активные проекты |
| `/project new <имя>` | создаёт проект и выбирает его |
| `/project select <id>` или `/project use <id>` | выбирает активный проект |
| `/project free` или `/project none` | переходит к свободной работе |
| `/project status` или `/project current` | показывает текущий проект |
| `/project archive <id>` | архивирует проект |
| `/project unarchive <id>` | повторно активирует архивный проект |
| `/project help` | справка |

`select` и `archive` используют **id** проекта, а не заголовок.

В свободной работе память проекта не читается и не записывается; чат,
сводка и навыки остаются доступными.

## 2.3 Память

| Команда | Поведение |
|---|---|
| `/memory` или `/memory help` или `/memory ?` | справка |
| `/memory list [candidate\|confirmed\|archived]` | перечисляет навыки и счётчики |
| `/memory show <slug>` | показывает навык |
| `/memory review` | интерактивная проверка кандидатов |
| `/memory confirm <slug>` | подтверждает навык |
| `/memory archive <slug>` | архивирует навык |
| `/memory archive search <текст>` | ищет в архивных транскриптах |
| `/memory archive read <session> [offset] [limit]` | читает архивный транскрипт |

Слова `search` и `read` зарезервированы: slug навыка, называющийся
ровно `search` или `read`, нельзя архивировать этой командой.

Команды удаления не существует: допускается только архивирование.

## 2.4 Что не является командой

Инструменты (`filesystem.*`, `memory.*`, `mcp.*`, `clock.now`, ...) вызываются
моделью через registry. Они не вводятся как `/tool`.
Единственное исключение — информационные команды `/tools`, `/status`, `/mcp`,
`/audit`, которые являются консольными, а не инструментами.

# 3. Командная строка

```text
hagar [опции]
```

| Опция | Эффект |
|---|---|
| `--config PATH` | использует явный файл конфигурации |
| `--model NAME` | переопределяет `model.name` |
| `--project NAME` | выбирает активный проект при запуске |
| `--free` | запускает в режиме свободной работы |
| `--no-memory` | отключает память и проекты для сессии |
| `--no-native-tools` | включает текстовый JSON-протокол |
| `--version` | печатает версию |

`--project` и `--free` взаимоисключающие.

## 3.1 Поиск конфигурации

Порядок:

1. `--config PATH`
2. переменная `HAGAR_CONFIG`
3. `./hagar.yaml` в текущем каталоге

Относительные пути внутри `hagar.yaml` — аудит, политика, Vault — разрешаются
относительно каталога файла конфигурации, а не каталога, из которого
вы запускаете Hagar.

## 3.2 Коды выхода

| Код | Значение |
|---|---|
| `0` | нормальный выход или `--version` |
| `1` | ошибка конфигурации или недействительный проект |
| `130` | прерывание по Ctrl-C |

Ошибка MCP не меняет код выхода: она регистрируется, и
harness продолжает работу.

# 4. `hagar.yaml`

Минимальный пример:

```yaml
model:
  provider: ollama
  name: llama3.1:latest

vault:
  path: ./vault

filesystem:
  sandbox:
    - alias: workspace
      path: .
      permissions: RX
```

## 4.1 `model`

| Поле | По умолчанию | Примечания |
|---|---|---|
| `provider` | обязательно | `ollama`, `deepseek`, `claude`, `gemini` |
| `name` | обязательно | имя модели у провайдера |
| `host` | значение провайдера по умолчанию | базовый URL API |
| `native_tools` | `true` | если `false`, используется текстовый JSON-протокол |
| `max_tokens` | `1024` | используется только Claude |
| `api_key_env` | стандартное имя | переменная окружения ключа |

Провайдеры и ключи:

| Провайдер | Стандартный ключ |
|---|---|
| `ollama` | нет |
| `deepseek` | `DEEPSEEK_API_KEY` |
| `claude` | `ANTHROPIC_API_KEY` |
| `gemini` | `GEMINI_API_KEY` |

Ключи никогда не следует записывать в YAML. Если ключ отсутствует, клиент
не создаётся, и запуск завершается с явной ошибкой.

При активном нативном вызове Hagar использует структурированные инструменты
провайдера. Если провайдер отклоняет схему (HTTP 400/404/422), на первом
шаге происходит переход на текстовый JSON-протокол для этой сессии. Fallback
покрывает техническую ошибку, но не гарантирует, что модель выберет инструмент правильно.

## 4.2 `audit`

```yaml
audit:
  enabled: true
  path: logs/audit.jsonl
  max_field_chars: 2000
  max_bytes: 5000000
  max_files: 100
  include_outputs: true
```

| Поле | По умолчанию | Эффект |
|---|---|---|
| `enabled` | `true` | включает/отключает журнал |
| `path` | `logs/audit.jsonl` | файл JSON Lines |
| `max_field_chars` | `2000` | усекает поля |
| `max_bytes` | `5000000` | порог ротации |
| `max_files` | `100` | количество сохраняемых ротированных файлов |
| `include_outputs` | `true` | если `false`, редактирует вывод инструментов |

Аудит содержит чувствительные данные: вывод файлов, ответы и тексты. Его нужно
защищать так же, как workspace. `/audit` показывает только события текущего
файла, а не ротированные.

Основные события: `harness.start`, `turn.start`, `llm.tool_choice`,
`tool.call`, `tool.result`, `turn.answer`, `permission.decision`,
`permission.confirmation`, `memory.*`, `mcp.loaded`, `mcp.failed`,
`harness.stop`.

## 4.3 `policy`

```yaml
policy:
  path: policy.yaml
  subject: assistant
```

`path` задаётся относительно конфигурации. Если файл нечитаем или
недействителен:

- все политики становятся `DENY`;
- регистрируется `policy.failed`;
- Hagar остаётся запущенным, но ни один инструмент не выполняется;
- консоль показывает `Policy: DENY ALL`.

## 4.4 `vault`

```yaml
vault:
  path: ./vault
```

Это корень памяти Markdown. Он должен существовать и быть доступным для записи.
Если он отсутствует или недоступен для записи, память отключается с предупреждением;
остальная часть harness продолжает работу.

## 4.5 `memory`

```yaml
memory:
  enabled: true
  vault_subdir: Hagar
  context_turns: 10
  context_skills: 3
  context_project_memories: 10
  max_context_chars: 6000
  project_max_active: 200
  summary_max_chars: 4000
  max_skill_chars: 4000
```

| Поле | По умолчанию | Эффект |
|---|---|---|
| `enabled` | `true` | включает память |
| `vault_subdir` | `Hagar` | подкаталог внутри Vault |
| `context_turns` | `10` | внедряемые последние ходы; `0` отключает |
| `context_skills` | `3` | внедряемые подтверждённые навыки |
| `context_project_memories` | `10` | заголовки активных решений |
| `max_context_chars` | `6000` | бюджет блока памяти |
| `project_max_active` | `200` | порог обслуживания проекта |
| `summary_max_chars` | `4000` | максимальная длина сводки |
| `max_skill_chars` | `4000` | максимальная длина навыка |

`vault_subdir` должен оставаться внутри Vault: абсолютные пути, `..`,
`I:/...` и другие буквы дисков Windows отклоняются даже в Linux.

Бюджет измеряется в **символах**, а не в токенах. Когда блок
усекается, аудит регистрирует `memory.context_trimmed`.

## 4.6 `filesystem`

```yaml
filesystem:
  sandbox:
    - alias: documenti
      path: C:\Users\pippo\Documenti
      permissions: RWX
  limits:
    max_write_bytes: 0
    min_free_bytes: 0
    session_write_bytes: 0
    ask_over_bytes: 0
```

Каждая запись:

| Поле | Обязательно | Примечания |
|---|---|---|
| `alias` | да | один сегмент, уникальный без учёта регистра |
| `path` | да | существующий каталог хост-системы |
| `permissions` | нет | по умолчанию `R`; буквы `R`, `W`, `X` |

Разрешения:

| Буква | Что покрывает |
|---|---|
| `R` | чтение, перечисление, поиск, `stat` |
| `W` | запись, создание, переименование, копирование, удаление |
| `X` | `chdir` в каталог |

Агент видит `/home/ai/<alias>/...`. `/home/ai` перечисляет alias, но
не является физическим каталогом, и войти в него с помощью `chdir` невозможно.

Ограничения:

- дублирующиеся alias и пути останавливают конфигурацию;
- отсутствующий путь останавливает конфигурацию;
- физические пути могут содержать пробелы; alias — нет;
- Hagar не создаёт каталоги sandbox и не предполагает наличие выделенной домашней директории.

Ограничения записи:

| Поле | Эффект |
|---|---|
| `max_write_bytes` | максимум для отдельной операции |
| `min_free_bytes` | минимальный остаточный свободный объём |
| `session_write_bytes` | максимальный суммарный объём за сессию |
| `ask_over_bytes` | выше этого порога запрашивается подтверждение |

`0` отключает отдельное ограничение. Ограничения являются инвариантами:
их превышение — это ошибка инструмента, а не предупреждение.

## 4.7 `permissions`

```yaml
permissions:
  read: true
  write: false
  shell: false
  network: false
```

Это **системный предел**. По умолчанию: `read=true`, остальные `false`.

| Поле | Что предоставляет |
|---|---|
| `read` | filesystem read, memory read |
| `write` | filesystem write/create/delete, memory write |
| `shell` | `FILESYSTEM_EXEC` |
| `network` | `NETWORK` |

`COMPUTE` и `MCP_CALL` всегда входят в предел, но политика может их запретить.
Если предел не предоставляет capability, политика не может её предоставить.

## 4.8 `rag`

```yaml
rag:
  top_k: 8
```

Значение, предусмотренное для поиска по документам. В этой версии оно не изменяет
контекст памяти.

## 4.9 `mcp_servers`

```yaml
mcp_servers:
  - endpoint: https://mcp.example.com/mcp
    namespace: example
    auth:
      type: bearer
      token_env: MCP_EXAMPLE_TOKEN
```

Поля:

| Поле | Примечания |
|---|---|
| `endpoint` | URL HTTP/JSON-RPC сервера MCP |
| `namespace` | префикс импортированных инструментов: `mcp.<namespace>.*` |
| `auth` | необязательно: `bearer`, `header` или `oauth` |

Bearer/header:

```yaml
auth:
  type: header
  header: Authorization
  token_env: ATLASSIAN_BASIC
```

Значение, прочитанное из окружения, отправляется **как есть**: для Basic
оно уже должно быть `Basic <base64>`, а не только токен.

OAuth:

```yaml
auth:
  type: oauth
  oauth:
    authorization_server: https://auth.example.com
    client_id: ...
    client_secret_env: MCP_CLIENT_SECRET
    scopes: [read:me, offline_access]
    audience: api.atlassian.com
    redirect_port: 8765
    token_cache: .hagar/oauth/example.json
    timeout: 300
```

Поток — authorization code + PKCE с локальным callback
`http://localhost:<port>/oauth/callback`. Если `client_id` отсутствует, предпринимается попытка
динамической регистрации. При `offline_access` добавляется
`prompt=consent`. Токены хранятся в локальном файле с ограниченными правами и
обновляются автоматически.

Если сервер MCP даёт сбой:

- регистрируется `mcp.failed`;
- сервер пропускается;
- остальные серверы и остальная часть harness продолжают работу;
- `/mcp` показывает ноль инструментов для этого пространства имён.

# 5. `policy.yaml`

Пример:

```yaml
version: 1
subjects:
  assistant:
    default: deny
    rules:
      - capabilities: [FILESYSTEM_READ]
        effect: allow
        tools: ["filesystem.*"]

      - capabilities: [FILESYSTEM_WRITE, FILESYSTEM_CREATE]
        effect: ask
        tools: ["filesystem.*"]

      - capabilities: [COMPUTE]
        effect: allow
        tools: ["calculator.*", "statistics.*", "units.*",
                "clock.*", "calendar.*", "think.*", "text.*", "url.*"]

      - capabilities: [MCP_CALL]
        effect: ask
        tools: ["mcp.*"]

      - capabilities: [MEMORY_READ]
        effect: allow
        tools: ["memory.*"]

      - capabilities: [MEMORY_WRITE]
        effect: ask
        tools: ["memory.*"]
```

## 5.1 Эффекты

| Эффект | Значение |
|---|---|
| `allow` | инструмент может быть выполнен |
| `ask` | требуется подтверждение человека |
| `deny` | инструмент не выполняется |

Порядок строгости: `DENY > ASK > ALLOW`. При нескольких запрошенных capability
действует логика AND: побеждает худший эффект.

`ASK` без канала подтверждения эквивалентен `DENY`. Подтверждение из консоли
показывает `lo faccio? (y/N)`, значение по умолчанию — `N`.

## 5.2 Capability

| Имя | Назначение |
|---|---|
| `FILESYSTEM_READ` | чтение, перечисление, поиск, stat |
| `FILESYSTEM_WRITE` | изменение |
| `FILESYSTEM_CREATE` | создание, копирование, rename в место назначения |
| `FILESYSTEM_DELETE` | удаление |
| `FILESYSTEM_EXEC` | вход/выполнение в sandbox |
| `MEMORY_READ` | чтение памяти |
| `MEMORY_WRITE` | запись в память |
| `NETWORK` | сетевой доступ |
| `MCP_CALL` | вызов инструмента MCP |
| `COMPUTE` | локальное вычисление без сети/filesystem |

## 5.3 Правила и специфичность

Правило может фильтровать по:

- `tools`: glob по имени (`filesystem.*`, `mcp.atlassian.*`);
- `paths`: префиксы пути, записанного моделью;
- `namespaces`: префиксы пространства имён.

Побеждает наиболее специфичное правило: сначала по числу фильтров, затем по
длине префикса. При равенстве побеждает более строгий эффект.
Без правил действует `default` субъекта; безопасное значение по умолчанию — `deny`.

Область `paths` сравнивает путь, **записанный моделью**, а не путь,
разрешённый после `chdir`: абсолютный путь или смена каталога могут не
соответствовать, и это даёт `DENY` (fail closed).

## 5.4 Ошибки

Если `policy.yaml` недействителен, отсутствует capability или субъект
не существует:

- Hagar применяет `DENY` ко всем политикам;
- регистрирует `policy.failed`;
- показывает предупреждение;
- не выполняет ни один инструмент.

# 6. Поведение по умолчанию

| Ситуация | Поведение |
|---|---|
| Нет `hagar.yaml` | ошибка конфигурации, выход 1 |
| Недействительный YAML | ошибка конфигурации, выход 1 |
| Недействительная политика | полный DENY, harness запущен |
| Vault отсутствует/недоступен для записи | память отключена, harness запущен |
| `projects` недоступен для записи | проекты отключены, память активна |
| Нет активного проекта | свободная работа |
| Неинтерактивный запуск | свободная работа, если не заданы `--project`/`--free` |
| `--project` не существует | ошибка, выход 1 |
| Сервер MCP недоступен | `mcp.failed`, сервер пропущен |
| Модель/Ollama недоступны | ошибка хода, harness остаётся активным |
| Отсутствует ключ API | клиент не создан, ошибка при запуске |
| Инструмент запрещён | результат-ошибка модели, выполнение не происходит |
| Инструмент в `ASK` без подтверждения | отказ |
| Превышен лимит записи | ошибка инструмента, запись не выполняется |
| Файл больше 4096 байт при `read_file` | ошибка, используйте `read_chunk` |
| Страница сверх лимита | `has_more`/`next_offset` |
| Symlink | невидим; операция как с несуществующим путём |
| Hard link/mount/junction | не обнаруживаются; ответственность пользователя |
| Гонка TOCTOU | не контролируется; ответственность пользователя |
| Память недоступна во время хода | `memory.failed`, ход продолжается |
| Конец сессии с ходами | сводка, архив, проверка проекта |
| Проверка отклонена | решения-кандидаты с `auto_saved: true` |
| Проект сверх `project_max_active` | запрос на архивирование |
| Ctrl-C во время OAuth | callback закрыт, выход 130 |
| Неизвестная команда `/` | сообщение, не отправляется модели |

## 6.1 Конец сессии

При выходе, если память активна и есть ходы:

1. транскрипт перемещается в `archive/chat/`;
2. генерируется сводка (LLM, с механическим fallback);
3. сводка сохраняется со ссылкой и хешем;
4. если есть проект, LLM предлагает решения-кандидаты;
5. пользователь может их проверить; при отказе они остаются кандидатами.

Если ходов нет, сводка не создаётся.

## 6.2 Чего Hagar не делает

- не выполняет команды shell;
- не передаёт модели физические пути;
- не гарантирует изоляцию ОС: sandbox основана на путях;
- не контролирует hard link, mount, junction или TOCTOU;
- не удаляет чаты или навыки по давности;
- не шифрует Vault;
- не превращает автоматически навык или решение в истину.

---

# 7. Операционная безопасность

- Модель не является доверенной: политики и подтверждения — это средства контроля.
- Vault — это Markdown в открытом виде: он может содержать беседы и решения.
- Аудит может содержать вывод файлов: его нужно защищать.
- Ключи API находятся только в окружении.
- Токены MCP/OAuth находятся в локальных кешах с ограниченными правами.
- Не открывайте Ollama или LM Studio в сеть без необходимости.
- Hard link или mount внутри разрешённого каталога может раскрыть
  внешнее содержимое: Hagar их не обнаруживает.

# 8. Устранение неполадок

| Симптом | Проверка |
|---|---|
| `Policy: DENY ALL` | проверить `policy.yaml` и `policy.path` |
| `Memory: disabled` | существует ли `vault.path`? доступен ли для записи? |
| `Projects: disabled` | существует ли `vault.path/Hagar/projects`? |
| `Failed to load MCP server` | endpoint, токен, `/mcp` |
| `MCP auth token missing` | переменная, указанная в `token_env` |
| `MCP HTTP 401` | учётные данные/заголовок Basic или OAuth |
| `MCP HTTP 400` | протокол, сессия или параметры сервера |
| `read_file` слишком большой | использовать `read_chunk` |
| `PermissionError` | политика, разрешения `R/W/X`, путь вне sandbox |
| Инструмент не в списке | сервер MCP дал сбой или инструмент не зарегистрирован |
| Команда не распознана | `/help` |

При ошибке конфигурации Hagar завершается с кодом 1 и печатает
подробности в stderr. При ошибке хода модель получает
результат инструмента, а аудит сохраняет событие.
