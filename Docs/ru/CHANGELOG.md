# HAGAR — Changelog

Формат свободный, но стабильный: версии в порядке убывания, со ссылкой
на коммит, когда это полезно.

# 0.5.2 — 2026-11-08

## Краткое описание

Релиз консолидации: память SQLite, субагенты, vision, инструменты
решений, паспорта моделей, импорт/экспорт Markdown и input broker CLI.

## Ломающие изменения

- память по умолчанию больше не Vault Markdown: используется
  `%LOCALAPPDATA%/Hagar/memory.db` или `HAGAR_MEMORY_DB`;
- Vault не импортируется автоматически;
- бэкенд `markdown` остаётся доступным только как legacy;
- `memory.database` и `decisions.*` — новые разделы конфигурации.

## Новые бэкенды LLM

- Новый бэкенд `lmstudio` для локального сервера LM Studio,
  совместимого с OpenAI, по умолчанию `http://localhost:1234/v1`, без ключа, если
  он не настроен на сервере.
- Новый бэкенд `openai` (алиас `chatgpt`) для API OpenAI Chat
  Completions, ключ `OPENAI_API_KEY`, настраиваемый base URL.
- Оба бэкенда используют общий клиент, совместимый с OpenAI, с нативным
  вызовом инструментов и текстовым JSON fallback при HTTP 400/404/422.
- Настраиваемый `model.timeout` (по умолчанию 120 с), передаваемый всем
  бэкендам; полезен для больших локальных моделей.
- Обновлены `hagar.example.yaml` и итальянская документация.

- `/usage` в CLI для суммарных токенов сессии; тот же ledger

- Инструменты и провайдеры LLM — плагины: встроенные в `local_tools/plugins.py`

- Ошибки плагинов изолированы и регистрируются в аудите; policy и песочница

- Политика субагента строго более ограничительная, чем у родителя; политики

- Абсолютный тайм-аут 5 минут на субагента, кооперативный, с состоянием
  `timed_out`; `agent_id` во всех событиях аудита.
- ASK субагентов передаются пользователю через `ParentBridgeConfirmation`,
  тайм-аут 180 секунд и DENY по истечении срока; родительская LLM не одобряет.
- `vision.open` загружает PNG/JPEG/WebP из песочницы и прикрепляет их к ходу;
  `ToolResult.images` и цикл Agent обрабатывают мультимодальный канал
  без base64 в тексте. Аудио в roadmap.
- Память SQLite как первичный источник: `memory/sqlite_store.py`,
  `memory/database.py`, WAL и резервное копирование; команды `/memory sessions`,
  `/memory chat` и `/memory backup`. Проекты и решения в одной
  базе данных; бэкенд Markdown только legacy.
- Экспорт Markdown из базы данных через `/memory export <path> [--force]`:
  чаты, навыки, сводки, проекты и решения, атомарная запись.
- Импорт Markdown через `/memory import <path> [--force]`; FTS5 в
  первичной базе данных с `bm25`/`snippet` и fallback `LIKE`.
- CLI с `ConsoleInputBroker`: единственный читатель консоли, заголовок
  внимания и подтверждения ASK с `F5` allow / `F8` deny; fallback `y/N`.
  Broker сохраняет и восстанавливает терминал, в том числе при Ctrl-C.
- Новый класс инструментов `decision.*` с `decision.choose`: провайдер LLM
  локальный/удалённый и локальный линейный классификатор, проверенные вероятности,
  аудит `decision.result` и capability `DECISION`.
- Паспорта моделей и бенчмарки: `/models list|show|test|hardware`,
  задержка, JSON, вызов инструментов, дата последней проверки и определение
  CPU/RAM/GPU без обязательных зависимостей.
- Временный artifact store и внутренняя mailbox: `artifact.put`,
  `artifact.put_file`, `mailbox.send` для ребёнка; `artifact.read`,
  `artifact.list`, `mailbox.inbox/read/ack` для родителя. Capability
  `AGENT_DATA`, квоты и очистка в конце хода.
- `artifact.save_to` копирует artifact целиком в доступный для записи путь
  песочницы родителя; требует `AGENT_DATA`, `FILESYSTEM_WRITE` и
  `FILESYSTEM_CREATE`, с возможным подтверждением политики.
- Аудит `artifact.discarded` в конце хода для неэкспортированных artifact,
  с причиной `unread` или `read_but_not_saved`; персистентность остаётся
  отложенной.
- Аудит отключён: вкладка отключена с меткой `audit off`.
- Thinking показывает reasoning, предоставленный провайдером, иначе
  временную шкалу событий.
- Основа для будущего GUI, без `input()` или `print()` в сервисе.

# 0.3.0 — 2026-11-05

## Память проекта, сводки и архив

- Новая память проекта, отделённая от навыков:
  `Hagar/projects/<id>/index.md` и `decisions/<data>-<slug>.md`, со
  статусом `candidate`/`active`/`superseded`/`archived`, альтернативами,
  обоснованием, provenance и `auto_saved`.
- При запуске Hagar показывает активные проекты и «свободную деятельность»; команды
  `/project list|new|select|free|status` и переопределения `--project`/`--free`.
- В конце сессии транскрипт перемещается в `archive/chat/` и
  заменяется сводкой со ссылкой и хешем; механический fallback, если
  модель недоступна.
- Решения проекта предлагаются как `candidate` и проверяются
  в конце сессии; если пользователь отказывается, они остаются кандидатами с
  `auto_saved: true`.
- Контекст по индексу: сводка и заголовки активных решений, а не
  тела; детали через `memory.project_context`. Бюджет
  `max_context_chars` (символы, а не токены) и аудит
  `memory.context_trimmed`.
- `project_max_active` запускает запрос об архивировании
  проекта; архивирование обратимо и ничего не удаляет.
- Если каталог `projects` недоступен для записи, память остаётся активной,
  а проекты отключаются с `project.disabled`.
- Просмотр архива: `memory.archive_search` и
  `memory.archive_read`, команды `/memory archive search|read`, с
  фильтром по проекту и транскриптом, сохраняющим `project` во
  frontmatter. Архив никогда не внедряется автоматически.

## Команды консоли и руководство

- Новые команды чата: `/help`, `/tools [категория]`, `/status`, `/mcp`,
  `/audit [n]`.
- `/tools` группирует инструменты по категориям и показывает capability.
- `/status` сообщает модель, вызов, проект, память, аудит и
  файловую систему.
- `/mcp` перечисляет настроенные серверы, endpoint и импортированные инструменты.
- `/audit` читает последние события текущего журнала, не раскрывая
  невыбранные поля.
- Неизвестные команды `/` не отправляются модели.
- Новый `Docs/it/MANUAL.md` с командами, CLI, `hagar.yaml`,
  `policy.yaml`, значениями по умолчанию и поведением при ошибках.

## MCP, OAuth и чистое завершение

- Клиент MCP обновлён до `MCP-Protocol-Version` `2025-06-18` с
  fallback, повторным использованием `Mcp-Session-Id` и телом HTTP в ошибках.
- OAuth: опциональный `audience`, `prompt=consent` при `offline_access`,
  callback `http://localhost:<port>/oauth/callback`, scope в
  dynamic registration.
- Ctrl-C во время OAuth или хода закрывает локальный callback и завершает работу с
  кодом 130, без traceback.

## Локальные инструменты и filesystem v2

- Новый каталог `local_tools/` для локальных провайдеров: вычисления, статистика,
  преобразование единиц, время/дата и feed. Это не серверы MCP: они регистрируют
  `ToolDefinition` в registry.
- Добавленные инструменты: `calculator.evaluate`, `statistics.compute`,
  `units.convert`, `clock.now`, `calendar.date`, `think.echo`,
  `text.diff`, `url.parse`, `feed.read`.
- Filesystem: `list_dir`, `read_chunk`, `rename`, `copy_file`, `search`.
- Новые capability `COMPUTE` (локальные вычисления, всегда в потолке) и
  `NETWORK` (включается `permissions.network: true`); `feed.read`
  требует `NETWORK`.
- `permissions.network` в конфигурации; policy: `COMPUTE` allow для
  calculator/statistics/units, `NETWORK` ask для feed.
- `feedparser` в зависимостях; feed скачивается через
  `requests`, с тайм-аутом и лимитом 5 MB, и только по URL http/https.
- SSRF: обязательное разрешение DNS, только глобальные адреса
  (никакого loopback, частных сетей, link-local, multicast или зарезервированных),
  ручные перенаправления с повторной проверкой (максимум 3) и отказ для URL с
  учётными данными.
- Восстановлено разрешение `rename` песочницы, потерянное при
  расширении; `filesystem.rename` требует `rename` на источнике и
  `create` в назначении.
- Переименование `MCP_tools/` → `local_tools/`: это локальные провайдеры, а не
  серверы MCP; пакет, импорты, тесты и документация обновлены.
- Файловая система с виртуальным корнем `/home/ai`: `stat`, `list_dir`,
  `search`, `read_chunk` и сообщения инструментов больше не раскрывают
  физический путь; входные пути `/home/ai/...` принимаются.
- `read_chunk` выравнивает границы по символам UTF-8 и возвращает
  `next_offset`; он больше не разрывает многобайтовые символы.
- `read_file` отклоняет файлы больше 4096 байт и отсылает к `read_chunk()`,
  чтобы не загружать весь файл в context window.
- `list_dir` возвращает не более 100 записей на страницу, а `search` — 100
  результатов (максимум 500); оба поддерживают `offset`, `next_offset`,
  `has_more` и сообщение
  `voci: riportate X di Y; per continuare usa offset=Z`. Для больших
  деревьев лучше сузить pattern/path, чем перебирать страницы.
- Новые ограничения записи `filesystem.limits`:
  `max_write_bytes` на операцию, `min_free_bytes` как резерв,
  `session_write_bytes` суммарно и `ask_over_bytes` для подтверждения.
  Первые три — инварианты; `ask_over_bytes` проходит через preflight
  `ToolRegistry` и спрашивает один раз, даже если policy — `ASK`.
- Symlink для песочницы не существуют: они не показываются, не читаются,
  не преследуются и не удаляются; `chdir` по ссылке отвечает
  “Directory not found”. Решение проекта: они остаются невидимыми,
  даже если хост-файловая система их поддерживает.
- Hard link, mount и junction внутри разрешённых каталогов не
  контролируются и не обнаруживаются Hagar. Это не дефект: hard link — это
  второе имя того же inode, а mount может открыть другую
  файловую систему, оставаясь внутри префикса. Инструменты файловой системы не создают
  hard link. Для полной изоляции пользователь должен гарантировать, что в
  каталогах песочницы их нет. Ответственность пользователя,
  вопрос закрыт.
- TOCTOU: эта версия не использует `openat2`, `O_NOFOLLOW` на каждом
  компоненте или Windows handle, поэтому не гарантирует атомарность между проверкой
  и операцией. Гонка требует локального конкурентного процесса с
  доступом на запись: злонамеренный сценарий или скомпрометированная среда, а не
  обычное использование. Закрыто как ответственность пользователя; для полной изоляции
  нужны выделенный том, отдельный пользователь, mount namespace или
  контейнер.
- `filesystem.allowed` заменён на `filesystem.sandbox`: у каждой записи есть
  `alias`, `path` и разрешения `R`/`W`/`X`. Агент видит
  `/home/ai/<alias>/...`; никаких `hdN`, никаких томов или синтетических
  промежуточных каталогов. `/home/ai` перечисляет алиасы, но не является монтированием.
- Разрешения по алиасу: `R` чтение/листинг/поиск/stat, `W`
  запись/создание/переименование/копирование/удаление, `X` `chdir`; глобальные
  разрешения остаются потолком.
- Обязательный алиас, один сегмент, уникальный без учёта регистра, без
  зарезервированных имён Windows; записи песочницы остаются путями
  хост-системы, и Hagar не создаёт каталоги. Физические пути и внутренние имена
  могут содержать пробелы; алиас — нет.
- POSIX runner `tools/run_tests.sh`; `run_tests.ps1` и shim остаются
  специфичными для песочницы Windows. Обновлены команды бенчмарка.
- Исправления мультиплатформенности из CI: `vault_subdir` отклоняет также пути с
  диском Windows (`I:/...`) в POSIX; отказ по symlink больше не
  проглатывается `except OSError`, поэтому путь не разрешается
  вне песочницы.
- 832 теста пройдено, 2 пропущено в Windows; 834 пройдено, 0 пропущено в Debian
  Linux (2026-11-06), включая тесты symlink.

# 0.2.0 — 2026-11-04

Первый релиз с проверяемой памятью, нативным вызовом, MCP auth/OAuth,
retention аудита и устанавливаемой упаковкой.

## Память v2

- Жизненный цикл `candidate` → `confirmed` → `archived`: LLM предлагает,
  пользователь продвигает из CLI.
- Команды `/memory list`, `/memory show`, `/memory review`,
  `/memory confirm`, `/memory archive`.
- Автоматическое внедрение только подтверждённых навыков, до
  `memory.context_skills` (по умолчанию 3), по лексическому совпадению; кандидаты
  и архивные остаются вне.
- `reviewed_at` во frontmatter; события аудита `memory.review` и
  `memory.status`.
- Retention, вариант A: никакого автоматического удаления; `archive`
  обратим с помощью `confirm`.
- `memory.context_skills` в конфигурации; 552 теста пройдено, 1 пропущен.

## Интерактивный MCP OAuth

- Поток authorization code + PKCE с callback на `127.0.0.1` и
  открытием браузера; ручной fallback с вставкой URL.
- Discovery RFC 9728 (protected resource) и RFC 8414 (authorization
  server), с динамической регистрацией клиента, если `client_id` отсутствует.
- Локальный кэш токенов с правами `0600`, автоматический refresh и один
  повтор при `401`.
- Конфигурация `auth.type: oauth` с `authorization_server`, `client_id`,
  `client_secret_env`, `scopes`, `redirect_port`, `token_cache`,
  `timeout`.
- Ограничения: нет device flow, DPoP, mTLS или client assertion.
- 522 теста пройдено, 1 пропущен.

## Retention аудита

- Ротация в `<file>.<timestamp>` сверх `audit.max_bytes`.
- `audit.max_files` (по умолчанию 100) ограничивает число файлов аудита,
  включая активный; самые старые резервные копии удаляются.

## Filesystem v2, математические инструменты и feed

### Файловая система

- `filesystem.list_dir`: нерекурсивный листинг содержимого каталога.
- `filesystem.list_dir` возвращает полные метаданные через `FileInfo` для каждого найденного элемента.
- `filesystem.read_chunk`: инкрементальное чтение больших файлов через offset и длину.
- `filesystem.read_chunk` работает на уровне байтов и возвращает `has_more`, чтобы агент мог продолжить чтение.
- `filesystem.rename`: переименование или перемещение файлов внутри песочницы.
- `filesystem.copy_file`: копирование файлов с проверкой разрешений и свободного места.
- `filesystem.search`: рекурсивный поиск по glob-шаблону (`*.py`, `*.md` и т. д.).
- `filesystem.search` возвращает:
  - общее число найденных результатов;
  - число возвращённых результатов;
  - признак усечения (`truncated`);
  - список результатов как `FileInfo`.
- Улучшено автономное исследование песочницы: агент теперь может перечислять каталоги, искать файлы и читать очень большие документы, не насыщая context window.
